# 🛡️ รายงานโครงสร้างระบบรักษาความปลอดภัย (Security Architecture Report)

**Project/System:** ResolvNow (Smart City Platform)  
**Security Status:** ✅ Highly Secured (Enterprise Grade Baseline)

---

## 1. ภาพรวมระดับความปลอดภัย (Executive Summary)
ระบบ **ResolvNow** ได้รับการออกแบบสถาปัตยกรรมด้านความปลอดภัยใหม่เพื่ออุดช่องโหว่ (Vulnerabilities) ที่พบได้บ่อยใน OWASP Top 10 โดยมีการใช้เทคนิครักษาความปลอดภัยทั้งฝั่งเซิร์ฟเวอร์ (Backend) และฝั่งผู้ใช้ (Frontend) ร่วมกันแบบ **Defense-in-Depth** ทำให้สามารถทนทานต่อการโจมตีทางไซเบอร์ได้ในระดับที่พร้อมใช้งานจริง (Production-Ready)

---

## 2. การป้องกันภัยคุกคามหลัก (Threat Mitigations)

### 2.1 ป้องกันการโจมตีแบบ XSS (Cross-Site Scripting)
> [!IMPORTANT]
> **ระดับความอันตราย:** รุนแรง (Critical) — ถูกแก้ไขเรียบร้อยแล้ว
* **กลไกที่ใช้:** ระบบมีการใช้งานฟังก์ชัน `escapeHTML()` ในระดับ Frontend ทุกหน้า (Citizen, Technician, Admin)
* **ผลลัพธ์:** หากมีผู้ไม่ประสงค์ดีพิมพ์โค้ดอันตราย (มัลแวร์สคริปต์) ลงใน "รายละเอียดการร้องเรียน" หรือ "ชื่อผู้ใช้" ระบบจะจัดการเข้ารหัสอักขระพิเศษ (เช่น `<` เป็น `&lt;`) ทั้งหมด ทำให้สคริปต์เหล่านั้นไม่สามารถทำงานได้และแสดงผลเป็นข้อความธรรมดาแทน ป้องกันการถูกขโมย Session หรือการควบคุมบัญชีผู้ดูแลระบบ 100%

### 2.2 ป้องกันการเชื่อมต่อฐานข้อมูลโดยมิชอบ (NoSQL Injection)
> [!WARNING]
> **ระดับความอันตราย:** ปานกลาง-สูง (Medium/High) — ถูกแก้ไขเรียบร้อยแล้ว
* **กลไกที่ใช้:** ติดตั้งและเปิดใช้งาน `express-mongo-sanitize` เป็น Middleware ด่านหน้า
* **ผลลัพธ์:** สิ่งที่ผู้ใช้ส่งมาไม่ว่าจะผ่าน API หรือช่องกรอกข้อมูล จะถูกสแกนเพื่อลบตัวแปรประมวลผล (Operator) ของ MongoDB เช่น `$gt`, `$ne` ออกทั้งหมด ทำให้แฮกเกอร์ไม่สามารถแอบอ่านข้อมูลบั๊กของฐานข้อมูลเพื่อหลอกระบบล็อกอินได้ นอกจากนี้ยังมีการตรวจสอบ Type Validation ดักไขปัญหาเซิร์ฟเวอร์แครชแบบ DoS ไว้แข็งแกร่ง

### 2.3 ป้องกันข้ามสิทธิ์และสวมรอย (Broken Access Control / BOLA)
> [!CAUTION]
> **ระดับความอันตราย:** สูง (High) — ถูกแก้ไขเรียบร้อยแล้ว
* **กลไกที่ใช้:** สร้างระบบ **Strict Role-Based Access Control (RBAC)** 在 API ทุกเส้น
* **ผลลัพธ์:** 
  - การจ่ายงาน (Assign Ticket) สงวนสิทธิ์คุ้มกันเฉพาะ **Admin** เท่านั้น
  - การเปลี่ยนสถานะงาน (Status Update) ถูกจำกัดให้เฉพาะ Admin และ Technician ที่รับผิดชอบเท่านั้น
  - หากประชาชนหรือบอทพยายามบังคับจบงานตัวเองผ่านระบบ API ด้วย POST/PUT Request โดยตรง จะโดนเตะออกและรับ `403 Forbidden` ทันที

## 3. การปกป้องเซิร์ฟเวอร์ (Server & API Hardening)

### 🚦 3.1 ระบบต้านทานการยิงเว็บ (Rate Limiting & Anti-Brute Force)
* **กลไก:** ใช้ `express-rate-limit` จำกัดความถี่ 
* **การปกป้อง:** ป้องกันการสแปมดึงข้อมูล (DDoS/Spam) และการคาดเดารหัสผ่าน (Brute Force) โดยจำกัดเส้นทาง Auth/Login ให้ขอ OTP หรือล็อกอินได้ **ไม่เกิน 30 ครั้งต่อ 15 นาที** (ต่อ 1 ไอพี) เป็นการประหยัดทรัพยากรการส่ง SMS/Email และลดภาระ Database มหาศาล

### ⛑️ 3.2 กรองส่วนหัวเครือข่าย (Helmet Security Headers)
* ระบบมีการสวม "หมวกนิรภัย" ให้กับ HTTP Response ผ่านไลบรารี `helmet` โดยปรับจูน Header อัตโนมัติ:
  - `X-Frame-Options: DENY` (กันการเอาเว็บเราไปแปะซ่อนหลอกคลิก Clickjacking ในเว็บอื่น)
  - `X-Content-Type-Options: nosniff` (ดับการเปลี่ยนชนิดไฟล์อันตราย)
  - `Strict-Transport-Security` (คุ้มครองการเชื่อมต่อแบบ HTTPS อย่างเข้มงวด)

## 4. มาตรฐานการพิทักษ์ข้อมูลผู้ใช้ (Session & Data Security)

> [!TIP]
> **Architecture Overview**
> Session Authentication ของ ResolvNow ผสานระหว่าง **Bcrypt** และ **Cookie Flags**

1. **Password Hashing:** รหัสผ่านทุกตัวในฐานข้อมูลเข้าหัสทางเดียวด้วยอัลกอริทึม `bcrypt` (Salt 10 Rounds) ต่อให้ Database ถูกเจาะ แฮกเกอร์ก็ไม่สามารถเอารหัสผ่านดิบไปใช้ต่อได้
2. **Strict Session Cookies:** รหัสคุกกี้เข้าใช้งาน (MongoStore Session) ถูกกำหนดสิทธิ์ด้วย:
   - `httpOnly: true` (สคริปต์หน้าเว็บใดๆ รวมถึงแฮกเกอร์ ไม่มีสิทธิ์ขโมยคุกกี้ยกเว้นบราวเซอร์เอง)
   - `sameSite: 'lax'` (ป้องกันการแอบส่งรีเควสต์ข้ามโดเมน หรือ CSRF)
   - `secure: true` (บังคับส่งผ่าน HTTPS เท่านั้นเมื่อขึ้นโหมด Production)

## 5. บทสรุป (Conclusion)
ระบบ ResolvNow ปัจจุบันได้ประยุกต์ใช้เทคโนโลยีรักษาความปลอดภัยในระดับ **Enterprise Baseline** แล้ว โครงสร้างการทำงานภายในถูกหุ้มเกราะหลายชั้น (Multi-layer Defense) ซึ่งสามารถนำเอกสารชุดนี้ไปอ้างอิงและสร้างความเชื่อมั่นให้กับผู้พัฒนา/ผู้ตรวจสอบระบบภายนอก หรือผู้บริหารได้เลยว่า **"ข้อมูลของประชาชน และระบบการดูแลตั๋วงาน ถูกปกป้องไว้อย่างรัดกุมที่สุดแล้ว"** 🛡️🚀
